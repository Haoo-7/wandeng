# 设计记录

视觉构思：酒店床头灯。首页上半截是无字房间照片，下半截是带静物图的横卡。

素材：
- `hotel.jpg` 从首页设计稿去字后得到
- `thumb-tod.png` / `thumb-dice.png` 从设计稿卡片照片裁切
- `thumb-wheel.jpg` 新生成的轮盘静物
- 正文、按钮、骰子点数用代码

未采用整图当页面。骰子页保留 CSS 三维骰，因为要显示中文动作／部位。

## v21（2026-10-02）· 同一晚、同一盏灯

四轮评审（design/critique/handoff.md）后的重制：

- 素材整套重拍：`hotel.jpg`（设置屏，床头柜上两杯酒 + 领带）与 `hotel-home.jpg`（首页，床上手机与远处的灯）两张不同场景；四张缩略图 `game-*.jpg` 与 hero 用同一光源方向（左上灯晕）、同一色温、同一颗粒——生成后经 `output/imagegen/grade.py` 统一调色（暗部压向 #14090D、加 35mm 颗粒）。
- 设置屏去流水线：两人称呼并排成一对，今晚热度放大为屏内锚点（选中档改灯金），安全词收成一行小注脚。
- 首页改「今晚的目录页」：头牌（真心话大冒险）整宽 + 三件小静物一排；缩略图去描边；服务单维持裸清单（明文决策不动）。
- 细节：热度选中并入灯金系统（--lamp 调深至 #DFB489）、圆角收两档 16/10、AFTER HOURS 字距 0.26em、字阶拉开（字标 22 / 巨标 34–46）、tab 灯芯 44×3 圆头、静物图与输入框描边各自归位。

三轮独立 critic（只看图、全新上下文）评分：7 → 7.5 → 7.8（设置 8 / 首页 7.5），均 pass，无「渲染事故」级问题。遗留两项已知取舍：首页服务单保持裸清单（§D-2 明文决策）；设置屏中部暗区是房间暗部的延伸，critic 读作有意留白。生成与调色脚本存于 output/imagegen/grade.py，原始生成图不入库。

## v23（2026-10-02）· 玩法诚实化

四条用户反馈落地：

- 首页「没有盒子」修正为「盒在图上」：圆角与裁剪收进 .media 图片壳，图注移出裁剪区——「真/掷/转/答」的字脚不再被圆角啃掉；波纹随之注入 .media。
- 骰子去点数化：动作骰与部位骰的六面直接刻上该档的动作/部位（数据每档恰好 6×6），掷出即读面，结果纸只承担那句怎么做。
- 轮盘发牌化：进屏发八句上盘，每扇刻那句话的头几个字（象牙扇墨字、深漆扇奶油字），转角按落点反解——停在哪扇念哪句，转盘从随机动画变成真正的抽签器。
- 飞行棋：掷骰改为 3D 点数骰浮层（reduceMotion 直接走格）；两枚棋子撞进同一格触发「追上」——天意抽一件两个人一起做的事；到终点分出胜负后，判词写明「输家得满足赢家一个条件，现在就提，今晚有效」。

## v24（2026-10-02）· 签筒轮盘与飞行棋动画

用户反馈两条 + 参考 couple-stark 后的原创改进：

- 轮盘从「八扇发八句」改为**签筒发牌**：整池（30+ 句）洗成一筒，12 支上盘为窗口，落过的扇在下次转动前从筒里补新签，筒摇空整池重摇；盘下常驻「签筒里还剩 N 支 · 下一支」一行。与参考项目「牌堆即盘面」的静态 12 条不同，这里全池轮转、盘面始终可读。扇面 conic 由 JS 逐扇生成（修掉一处漏 % 的无效声明）。
- 飞行棋掷骰动画强化：浮层骰先蓄力 240ms 再抛出翻滚 1.25s，面板小骰同步跳面，首掷前强制 reflow 保证过渡生效。
- 棋盘上的「两个人一起」（同格追上 / together 格）只发房间堆——棋局发生在酒店房间，出门堆不上桌。
- 行为校验：轮盘连续 5 转落点与结果卡全对（修正校验公式的半扇偏移后），签筒计数随转递减。

## v25（2026-10-02）· 轮盘可读性重构（couple-stark 结构）

用户指出刻在扇面上的字看不清，要求参考 couple-stark。实拍该站确认其可读性来源：盘面无字、结果区常驻、选项列清单。据此重构轮盘屏：

- 盘面去句子刻字，只刻序号 1–12（与清单一一对应）；序号反向旋转抵消盘角（transition 与 .wheel 同曲线），盘转字不转，任何时刻正立。
- 结果纸常驻：没开转是灰态「还没开转」，落定写明「盘上第 N 支 + 那句话 + 谁来做」。
- 新增「本轮选项」两栏编号清单：盘上十二支的全文名单，刚落过的一行奶油高亮、序号点灯金；表头带签筒余量。
- 动作区（转动/过/换人）提到清单之前，再转不用滚屏。
- 签筒机制不变：整池 30+ 洗成一筒，落一支补一支，筒摇空重摇。
- 行为校验：4 转落点序号 = 结果卡 = 清单高亮行全对，筒计数递减。

## v26（2026-10-02）· 收灯：事后安慰仪式

参考 couple-stark 的「余韵收尾」（抱抱、补水、复盘、夸奖，把今晚舒服地收住），补上晚灯缺失的情绪架构：此前每个玩法都是无限抽卡循环，唯一出口是左上角返回——今晚没有「结束」这个动作。

- **新屏「收灯」**：固定三步仪式，不是第十个玩法。① 安抚 → ② 复盘 → ③ 收住，面板一步步亮起（没走到的步骤不在屏上），每步从自己的桶里抽一句；走完只剩一颗金色「熄灯」，按下后金色离场、房间沉到 `--room-sunk`，居中一行「晚安」+ 两个人的名字（暖金 = 灯还亮着，熄灯后屏上不再有金——token 语义自己完成了叙事）。
- **aftercare 内容池**：soothe / debrief / close 三桶各 6 句，不分热度、不分性别（无她/他），措辞按晚灯声线重写；自定义导入契约新增 `aftercare` kind（`{bucket, text}`，heat/gender 参与校验但不参与抽取）。
- **入口两处**：首页服务单下方单独一组「散场 · 收灯」（不进「也可以玩」——收灯不是玩法，裸清单决策不动）；飞行棋终局把「玩法」切换让位给「收灯」，与「再来一局」并排。
- 决策记录：状态只存内存，不持久化（与界面态不持久化同一条原则）；去重键两段式 `aftercare-<bucket>`（USED_KEY_RE 约束）；文本去重测试含全桶查重与性别代词守卫。
